# Mandi Cafe & Grill — website

Marketing site for Mandi Cafe & Grill, 734 Crabb River Rd, Richmond, TX.
Static output (Vite + vanilla TypeScript), a procedural Three.js hero, GSAP
scroll reveals. No framework, no cookies, no tracking.

## Run

```sh
cd mandi-cafe
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ + robots.txt + sitemap.xml + JS budget check
npm run preview    # serve dist/ on :4173
```

Other scripts:

| Script | What it does |
|---|---|
| `npm run images` | Processes `assets/img/source/*` into `public/img/` (AVIF/WebP/JPEG at 640/1280/1920, blurred placeholders) and writes `src/content/images.json`. Also regenerates the favicon PNGs. |
| `npm run poster` | Renders the 3D hero to `assets/img/source/hero-poster.png` and `public/og.jpg` with headless Chromium. Run `npm run images` afterwards. |
| `npm run screenshots` | Full-page and per-section screenshots at 360/390/768/1024/1440/1920 plus reduced-motion and no-WebGL fallbacks → `docs/screenshots/`. |
| `npm run lighthouse` | Lighthouse mobile + desktop for both pages → `docs/lighthouse/`. |
| `npm run typecheck` | `tsc --noEmit`. |
| `node scripts/contrast.mjs` | WCAG AA check of every text/background pair. |

Headless scripts look for Chromium at `$CHROME_PATH` or the Playwright path
(`/opt/pw-browsers/...`). Set `CHROME_PATH` on other machines.

## Editing content (owner-facing)

Everything factual lives in **`src/content/site.json`**: name, address, phone,
hours, menu, story, gallery order, social and ordering links. Edit it and
rebuild. No code changes needed.

- **Hours**: `hours.weekly` uses 24-hour `"HH:MM"` ranges per day. Use `"24:00"`
  for midnight. The open/closed badge is computed from these in
  `America/Chicago`.
- **Menu**: `menu.categories[].items[]`. `price: null` shows "Ask". `serves`
  adds a "serves 3–4" note. Set `image` to an image id to show a photo on a
  signature dish.
- **Signature dishes**: `signatures` lists item ids, in order.
- **Gallery**: `gallery.images` lists image ids (aim for 8–12).
- **Confirmation flags**: any object with `"confirmed": false` is listed in the
  visible *Build notes* section at the foot of every page. Set the value, then
  change `confirmed` to `true`. Set top-level `"buildNotes": false` to remove
  the section entirely at launch.

## Replacing photos

1. Copy the owner's original files into `assets/img/source/`.
2. Add an entry per file to `assets/img/source/manifest.json` with a real
   `alt` (what dish or space it shows) and its origin.
3. Record the file and the owner's approval in `assets/img/CREDITS.md`.
   Do not use Google Maps photos without approval; they are user-uploaded
   and copyrighted.
4. `npm run images`, then reference the ids in `site.json`.

Sources narrower than 1280 px are flagged: use them small, never as a hero.

## Hero 3D

`src/scene/hero.ts` builds the tray, rice, garnish and drifting spices from
primitives (no model download). It boots after `load` + idle, only if WebGL
is available and neither `prefers-reduced-motion` nor Save-Data is set;
otherwise the poster `<picture>` (the LCP element) stays. Rendering pauses
when the hero is off-screen or the tab is hidden. DPR is capped at 2.
Shadows and half the rice are dropped on small or low-core devices.

Debug query flags: `?scene=1` boots the scene immediately, `?poster=1` also
fills the viewport with it (used by `npm run poster`), `?nowebgl=1`
simulates a WebGL failure.

## Deploy

Static output in `dist/`. `vercel.json` sets the build command, output dir,
immutable caching for fonts/images and security headers. Create a separate
Vercel project with **Root Directory = `mandi-cafe`**, or point Netlify /
Cloudflare Pages at `mandi-cafe` with build `npm run build`, publish `dist`.

Before launch set `siteUrl.value` in `site.json` to the real domain: it feeds
the canonical URL, Open Graph tags, `sitemap.xml` and JSON-LD.

## Layout

```
mandi-cafe/
  PROMPT.md               the build brief
  index.html, menu.html   templates (tokens filled from site.json at build)
  src/main.ts             entry
  src/scene/              hero.ts (Three.js), index.ts (lazy loader + fallbacks)
  src/lib/                hours, header, motion (GSAP), lightbox, tilt, map
  src/styles/             tokens, base, components, print
  src/content/site.json   the content (owner edits this)
  src/content/images.json generated by scripts/images.mjs
  scripts/                render (templating), images, poster, postbuild, screenshots, lighthouse, contrast
  public/                 fonts (self-hosted WOFF2), img (generated), favicon set, og.jpg
  assets/img/source/      originals + manifest.json;  assets/img/CREDITS.md
  docs/                   screenshots and Lighthouse reports
```

## Quality gates (last run)

Lighthouse 13, simulated throttling, run inside a cloud container with no
GPU (Chromium falls back to SwiftShader, a software renderer). Reports are in
`docs/lighthouse/`.

| Page | Perf | A11y | Best practices | SEO | LCP | CLS | TBT |
|---|---|---|---|---|---|---|---|
| Home, mobile, 3D path | 61 | 100 | 100 | 100 | 2.8 s | 0 | 8.9 s |
| Home, mobile, poster path (`?nowebgl=1`) | 93 | 100 | 100 | 100 | 2.8 s | 0 | 0 ms |
| Menu, mobile | 98 | 100 | 100 | 100 | 2.3 s | 0 | 0 ms |
| Home, desktop, 3D path | 37 | 100 | 100 | 100 | 2.8 s | 0.001 | 9.0 s |
| Home, desktop, poster path | 71 | 100 | 100 | 100 | 2.9 s | 0.001 | 0 ms |
| Menu, desktop | 81 | 100 | 100 | 100 | 2.3 s | 0 | 0 ms |

The 3D-path blocking time is the software renderer: building the environment
map and compiling shaders takes about 3.7 s there, versus tens of
milliseconds on a device with a GPU. The site detects that case (first frame
over 150 ms) and keeps the still image, but the one-off setup cost is still
recorded. Re-run `npm run lighthouse` on a machine with a GPU for the
representative 3D-path score; the poster-path row is the fair no-GPU number.

LCP is the poster image (AVIF, preloaded) on the home page and the heading on
the menu page. The desktop LCP figures above are dominated by the simulated
slow-4G network profile Lighthouse applies to desktop as well.

Other gates: `node scripts/contrast.mjs` passes every pair at AA or better;
JSON-LD (`Restaurant` on the home page, `Menu` on the menu page) parses and
carries name, image, address, telephone, cuisine, hours and menu URL. Paste
a deployed URL into Google's Rich Results Test after launch; it cannot run
against localhost.

Screenshots at 360, 390, 768, 1024, 1440 and 1920 px, per-section crops at
390 and 1440, plus reduced-motion and no-WebGL hero fallbacks, are in
`docs/screenshots/`.
